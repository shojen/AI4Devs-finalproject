_Previously: 2026-09-06 (first pass, same day) — No story in progress; a routine push surfaced a CI-only failure. Added the **Install libheif AVIF encoder plugin** step to the **Setup PHP** excerpt and a new blockquote explaining it: GitHub-hosted Ubuntu runners ship `libheif` with AVIF decode support but no encoder plugin installed by default (confirmed against [actions/runner-images#13728](https://github.com/actions/runner-images/issues/13728)), so Imagick silently wrote a 0-byte `.avif` instead of throwing — invisible locally because Sail's own `apt-get install php8.5-imagick` pulls the encoder plugin in as a `Recommends`. Full incident in [errors-log.md](../errors-log/2026-09-01-to-2026-09-07.md#github-actions-ubuntu-runner-ships-libheif-with-no-avif-encoder-so-imagick-silently-wrote-a-0-byte-avif--2026-09-06)._

_Previously: 2026-08-28 — Test-suite parallelization: the **Run Tests** step is now `php artisan test --parallel` rather than a plain `php artisan test`, with no `--processes` so paratest auto-detects the runner's core count. Added a paragraph explaining why CI needed no equivalent to the Sail/WSL2-specific `storage/framework/views` fix `--parallel` required locally — the runner's checkout has no bind mount in the loop. The proposed coverage-gate command was updated to keep `--parallel` alongside `--coverage --min=80`; nothing else about the proposal changed._

_Previously: 2026-08-27 — Story 0019 (Media Library upload and conversions — backend): the **Setup PHP** excerpt gained `extensions: imagick`, which is the first `setup-php` input this project added for a *correctness* reason rather than for tooling. Recorded with the reasoning rather than as a config line, because the tempting alternative is the wrong one: GD on this platform can encode WebP but **not AVIF** (verified — `gd_info()` reports an empty `AVIF Support`), so without the extension the conversion tests fail everywhere, and guarding them with `->skip(fn () => ! extension_loaded('imagick'))` would have turned the story's central acceptance criterion into a green tick asserting nothing on all three matrix legs. Sail already installs `php8.5-imagick`, so CI was the only gap. The coverage-gate proposal below is unchanged — this story adds no coverage requirement._

_Previously: 2026-08-26 — CI database connection gap (`ai-spec/tasks/ci-database-connection-gap.md`): added the cross-reference from **Database provisioning** to [commands.md's Database prerequisite section](../testing/ci/commands.md#database-prerequisite), which documents what a contributor must provision locally to satisfy the same `phpunit.xml` pin this section describes for CI. The **Database provisioning** paragraph itself was added in the same commit as the fix (`55ba248`) and needed no further correction — verified live against a real MySQL connection (866/866 tests passing) before this pass. Closes the doc-pass item this task's checklist left open._
