## Story 0101a — Invoice numbering sequences (backend)

- FD-1: one `invoice_sequences` row per series (`standard`, `corrective`), no per-year buckets. The issue instant is converted to `config('app.timezone')` once (`AllocateInvoiceNumber::toAppTimezone()`, public) and that moment gives both the year and the printed number; the counter restarts at 1 only when reset is on, `last_year` is not null and the year grew; the reset flag is consulted only at a year change — story 0101a.
- FD-3: lock order inside an issuing transaction is `invoice_settings` FOR SHARE, then `invoice_sequences` `ORDER BY series FOR UPDATE` (corrective before standard), always after the order lock and before the locking read of the order's invoices (gap-lock deadlock fix, story 0101b F-1) — story 0101a.
- FD-4: `AllocateInvoiceNumber::__invoke(InvoiceType, CarbonInterface)` takes no settings; the settings read under the share lock in `lock(list<InvoiceType>, CarbonInterface)` decide and are returned to the caller to snapshot — story 0101a.
- FD-12: `PeekNextInvoiceNumber::__invoke(InvoiceType, ?array $candidate = null, ?CarbonInterface $at = null)` takes raw partial input, validates field rules only (no cross-field rules; Save is the gate) before any model exists; `attributeNames()` now lives in the `InvoiceSettingValidationRules` trait — story 0101a.
- I1: `lock()` and `__invoke()` must run at the same `DB::transaction` nesting level. The allocator caches locked rows per `DatabaseTransactionRecord` and discards them when the record object changes; no record or an unlocked series (while others are) is a `LogicException`. Matters to 0101b, 0107, 0108 — story 0101a.
- Error keys: `invoice` (`numbering.clock_skew`), `number` (`numbering.overflow`), `start_at` (`numbering.start_already_issued`, `numbering.start_invalid`) — story 0101a.
- D-1: no `InvoiceSequenceFactory`; `UNIQUE(series)` plus migration-created rows make `create()` fail, so fixtures use `Tests\Support\Invoices\Numbering::arrange()` (updates the existing row) — story 0101a.
- D-2: `last_issued_at` is `dateTime`, not `timestamp` (app-timezone wall clock, no session-timezone conversion, no 2038 limit); DST fall-back ambiguity accepted, it can only refuse — story 0101a.
- No new permission: preview reuses `invoice-settings.view`, starting counter reuses `invoice-settings.manage` — story 0101a.

## Story 0101b — Issue standard invoice (backend)

- Tables: `invoices` (complete from day one: frozen snapshot, lifecycle `voided_at`, five collection columns, look snapshot; only `UNIQUE(number)` on numbering, collation makes it case-insensitive) and insert-only `invoice_lines`; `orders.invoice_out_of_date_at` (read here, written only by 0108). All FKs on `invoices` and `invoice_lines.invoice_id` restrict; `invoice_lines.order_item_id` is `nullOnDelete` (the only write a line receives) — story 0101b, FD-1/FD-2/FD-4.
- `invoices.logo_media_id` restrict vs `invoice_settings.logo_media_id` nullOnDelete is deliberate (frozen look) — story 0101b, FD-18. Accepted risks: N-1 (a future media-delete path must lock settings first) and I-1 (restrict FKs on `issued_by`/logo need clean refusals in future delete flows) — story 0101b.
- Immutability: `Invoice::MUTABLE_COLUMNS` = `voided_at` + five collection columns + `updated_at`; every delete throws; `InvoiceLine` update/delete throw; architecture test forbids query-builder writes to either table under `app/`. Through the application only; VeriFactu/TicketBAI out of scope — story 0101b, FD-3.
- Signatures: `IssueInvoice::__invoke(Order, ?string $amount = null): Invoice` (the only screen entry); `IssueInvoiceForOrder::__invoke(Order, ?string, ?User): Invoice` (ungated; callers `IssueInvoice`, `SendOrderInvoices` 0104, `MarkOrderAsPaid` 0106a, `IssueAutomaticInvoice` 0105, pinned by an architecture test); `CreateStandardInvoice::__invoke(Order $lockedOrder, ?string $amount, ?User, ?array $collected = null): Invoice` (re-locks the order, `LogicException` outside a transaction / for a fresh order); `ComputeOrderInvoiceBalance::__invoke(Order, bool $locking = false): array{billable, netInvoiced, uninvoiced, liveCount, components, invoicedComponents}`; `SplitInvoiceAmount::__invoke(string $amount, string $billable, string $uninvoiced, array $components, array $invoicedComponents): array`; `BuildInvoiceLines::itemised(iterable, string $storedTax, ?string $taxRate)` / `::adjustment(string, string $base, string $tax, ?string $taxRate)`; `AssertInvoicesAreCurrent::__invoke(Order, string $errorKey = 'invoice')`; `AssertNumberingFormatIsFree::__invoke(InvoiceSetting, CarbonInterface)`; `ResolveInvoiceLocale::__invoke(): string` — story 0101b.
- Authorization: catalog 47, Administrator 46; `InvoicePolicy` has `viewAny`/`view`/`create` only. `IssueInvoice` needs BOTH `invoices.create` and `orders.view`, one refusal log (`create` on `invoice`) before any state read — story 0101b, FD-13/FD-17, F-3.
- Lock order: `orders` FOR UPDATE -> settings FOR SHARE + sequence FOR UPDATE -> locking read of the order's invoices -> inserts; one `$at = now()` right after the order lock, no back-dating, no issue-date parameter. A plain read under REPEATABLE READ would break the cap; reading invoices before the sequence lock gap-lock-deadlocks two issuers — story 0101b, FD-12, F-1.
- Error keys: `amount`, `issuer` (`invoices.errors.issuer_incomplete`), `number`, `invoice`; refund screens pass `items` to the guard; numbering check throws on `<series>_prefix` — story 0101b, FD-19. Amount format: dot-decimal, max two decimals, ceiling 99999999.99 — FD-11.
- B-1 (code review): the concept line is stored in the store language via `ResolveInvoiceLocale` (default store language if `lang/{code}/invoices.php` exists, else fallback locale), never the ambient or admin locale; 0102 reuses it — story 0101b.
- Test support: `Tests\Support\Invoices\Invoicing` (settings(), defaultStoreLanguage(), manager(), order(), thousandOrder(), sum(), invoicesOf()); `InvoiceFactory` states are `standard()`, `corrective(Invoice $of)` and `forOrder(Order)` — story 0101b.
